# VERA Cloud - Voice-Enabled Recovery Assistant

**VERA-cloud** is the software implementation of the **AI-SoNar** ("AI Stroke Navigator") research prototype. It is an AI-powered, voice-first, **post-discharge stroke follow-up** system that conducts short, structured "micro-check-in" conversations with stroke survivors and their caregivers, asks plain-language questions about how they are doing, **flags concerning responses, and routes them to the human care team.** This cloud version runs on Azure AI services.

> **Naming:** *AI-SoNar* is the patient-facing research prototype; *VERA-cloud* (this repository, sometimes shown as "VERA Cloud") is the codebase that powers it. They refer to the same system.

## ⚠️ Safety & Scope (read first)

AI-SoNar is a **bounded, non-diagnostic, human-supervised check-in tool**. Specifically:

- It is **not** a diagnostic tool and does **not** give medical advice, recommend treatments, or change medications.
- It does **not** replace clinicians. Its job is to **collect information, flag concerns, and route them to the human care team**, which remains responsible for all clinical decisions.
- **All clinical and escalation logic is DRAFT**, pending sign-off by the clinical lead (Dr. Ramin Zand). Every clinical rule, threshold, and escalation message is marked in code and tracked in [`CLINICAL_REVIEW_NEEDED.md`](CLINICAL_REVIEW_NEEDED.md). Do not treat any of it as clinically validated.
- **Tier-1 (BE-FAST) red-flag detection fires from the patient's own words alone** — it is independent of patient history and is **never suppressed** by a user's self-reported urgency.
- **No real patient data is in this repository.** All testing uses a generated **synthetic** PCORnet CDM dataset (see [Synthetic Data](#-synthetic-data)).

## 🌟 Features

### Core Capabilities
- **Voice-First Interface**: Natural conversation flow with AI-powered speech recognition and synthesis
- **Structured Assessment**: Comprehensive post-stroke follow-up questionnaire covering:
  - General well-being and symptoms
  - Medication adherence and side effects
  - Follow-up care appointments
  - Lifestyle management
  - Daily activities and support needs

### Cloud Enhancements
- **Azure AI Integration**: Powered by Azure OpenAI, Speech Services, and AI Search
- **Real-time Streaming**: Sub-second ASR and TTS with streaming audio
- **RAG-Enhanced Conversations**: Context-aware responses using medical knowledge base
- **Auto-scaling**: Handles 10-100+ concurrent sessions with Azure Container Apps
- **High Availability**: 99.9% uptime with Azure infrastructure
- **Global Deployment**: Deploy to any Azure region worldwide

### Conversation Modes
1. **Guided Mode**: Traditional structured conversation flow
2. **RAG-Enhanced Mode**: AI-powered contextual responses with medical knowledge

### Role Tracks & Micro-Visit Scenarios
- **Role tracks**: Survivor / Caregiver / Clinician. Only the *framing/wording* changes by track — clinical content is identical across all three (`api/services/roles.py`).
- **Micro-visit scenarios**: six short scenarios = 3 clinical levels (routine / worsening / red-flag) × 2 roles (survivor / caregiver), generated by `scripts/generate_micro_scenarios.py` into `scenarios/micro_*.yml`.

## 🩺 Clinical Logic (DRAFT — requires clinician sign-off)

A tiered flagging engine (`api/services/flagging.py`) evaluates each patient response. **Every rule below is DRAFT and listed in [`CLINICAL_REVIEW_NEEDED.md`](CLINICAL_REVIEW_NEEDED.md) for clinician review.**

| Tier | Meaning | Behavior |
|------|---------|----------|
| **Tier 1 — Red flag** | Stroke warning signs (BE-FAST) + chest pain, loss of consciousness, fall-with-injury | Emergency guidance (call 911) + automatic escalation. **Fires from the patient's words alone**, independent of history and of user-reported urgency. |
| **Tier 2 — Urgent** | Worsening-but-non-emergent; context-raised using patient history (e.g. anticoagulant + bleeding/fall/missed dose, BP ≥180/120, diabetic glucose symptoms) | Routed for clinician review (same / next business day). Requires patient context; absent in generic mode. |
| **Tier 3 — Routine** | Stable, no concerning symptoms | Logged for routine follow-up. |

Patient history is injected as **background only** — used to ask better questions and personalize plain-language information, **never** to diagnose or to read the medical record back to the patient. With no patient ID, the system runs in **generic mode** (no history-dependent flags; Tier-1 still works). User-reported urgency is stored as a **separate, advisory** field and never overrides automatic flagging. Every history access is recorded in an append-only audit log with no clinical content (`api/services/audit.py`).

## 🧬 Synthetic Data

**This repository contains NO real patient data and NO PHI.** The patient-data layer is developed and tested against a **generated synthetic PCORnet Common Data Model (CDM v6.0)** dataset:

- Generated by `scripts/generate_synthetic_cdm.py` into `data/synthetic_cdm/` (5 tables: DEMOGRAPHIC, DIAGNOSIS, PRESCRIBING, VITAL, LAB_RESULT_CM, joined on `PATID`).
- **~6 fictional patients** with invented identifiers and dates; see `data/synthetic_cdm/README.md`.
- Uses **real coding systems** (ICD-10-CM, RxNorm, LOINC) with fictional values, so downstream code matches production shape.
- The data path is configurable via the `CDM_DATA_PATH` environment variable, so the team can later point it at the real (unshareable) CDM source **without any code change**.

See [`docs/SYNTHETIC_DEMO.md`](docs/SYNTHETIC_DEMO.md) to run the end-to-end flagging demo with no Azure required.

## 🚀 Quick Start

### Prerequisites
- Python 3.11+
- Docker
- Azure CLI
- Azure subscription

### Local Development Setup

1. **Clone and setup**
   ```bash
   git clone https://github.com/vafaei-ar/VERA-cloud.git
   cd VERA-cloud
   ./scripts/setup.sh
   ```

2. **Configure Azure services**
   ```bash
   # Create your .env from the template, then add your Azure details
   cp env.example .env
   # Edit .env with your Azure service endpoints and keys
   ```

3. **Run locally**
   ```bash
   source vera-cloud/bin/activate
   python -m uvicorn api.main:app --reload
   ```

4. **Access the application**
   - Open http://localhost:8000 in your browser
   - Test the voice interface

### Azure Deployment

1. **Deploy infrastructure**
   ```bash
   ./infrastructure/scripts/deploy.sh
   ```

2. **Access deployed application**
   - The script will output the application URL
   - Access via the provided URL

### API endpoints (added for the focus-group refinements)

| Method & path | Purpose |
|---------------|---------|
| `POST /session/start` | Start a check-in (role + optional PATID + caregiver consent gating). |
| `POST /api/session/{id}/urgency` | Record patient self-reported urgency (advisory). |
| `POST /api/session/{id}/reminder` | Save a voice-captured reminder. |
| `GET /api/session/{id}/clinician-summary` | Prioritized clinician summary (flags + urgency first). |
| `POST /api/session/{id}/field-action` | Workflow-fit usage metric. |
| `GET /api/resources` · `GET /api/resource-regions` | Local resource lookup by region + need. |
